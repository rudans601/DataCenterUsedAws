# 장애 사례 (예시): 트래픽 급증으로 응답 지연

## 상황
- 수강 신청 기간처럼 요청이 몰리면서 api 요청량이 평소의 수십 배로 늘었다.
- p95 응답 시간이 수 배로 늘었고, CPU 스로틀링 비율이 80%를 넘었다. 오류율은 1% 미만으로 낮았다.

## 원인
- Pod 2개의 CPU limit(100m)이 늘어난 요청을 처리하기에 부족했다.

## 근거
- CPU 사용량이 limit의 100% 가까이 유지되고 스로틀링 비율이 높음
- 최근 배포 이력 없음, Pod 상태 정상

## 조치
- 운영자 승인 후 복제본을 2개에서 4개로 늘렸다.
- 부하가 줄어든 뒤 다시 2개로 줄였다.

## 결과
- 증설 1분 뒤 p95 응답 시간과 스로틀링 비율이 크게 줄었다.

## 교훈
- 반복되는 트래픽 패턴이면 HPA를 설정해 자동으로 늘리고 줄이도록 한다.
