# 런북: 배포 후 오류율 증가·성능 저하와 롤백

## 증상
- 배포 직후부터 5xx 오류율이 오르거나 p95 응답 시간이 크게 늘어난다. Pod는 모두 Running·Ready라서 상태만 보면 정상처럼 보인다.
- 오류가 특정 비율로 꾸준히 섞여 나오거나 (예: 요청의 일부만 실패), 모든 요청이 일정하게 느려진다.
- 응답이 느려지면 같은 연결 수로 처리할 수 있는 요청량(req/s)이 오히려 줄어든다. CPU 사용률은 낮다.
- 로그에 응답 오류, 예외 메시지, 느린 처리 경고가 늘어난다.

## 원인 찾기
1. 배포 이력에서 현재 리비전이 언제 생겼는지, 직전 리비전과 무엇이 다른지(이미지, 실행 인자, 설정) 확인한다.
2. 오류율이 오르기 시작한 시점과 새 리비전 배포 시점이 맞는지 본다.
3. 부하 증가와 구분한다: 요청량이 늘지 않았고 CPU 여유가 있는데 오류나 지연만 늘었다면 배포 문제다.

## 조치
- 최근 배포가 원인으로 보이면 **직전 리비전으로 롤백**한다. 원인 분석은 롤백으로 서비스를 안정화한 뒤에 한다.
- 재시작은 같은 버전을 다시 띄우므로 배포 결함에는 효과가 없다.
- 복제본 증설도 오류 비율을 줄이지 못한다.

## 검증
- 롤백 후 오류율이 배포 이전 수준(1% 미만)으로 돌아왔는지, 응답 시간이 정상인지 확인한다.
- 배포 이력에 롤백 사유를 남긴다.
