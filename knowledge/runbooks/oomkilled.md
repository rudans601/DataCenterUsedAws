# 런북: 메모리 부족 (OOMKilled)

## 증상
- Pod의 마지막 종료 사유가 `OOMKilled`, exit code 137이다.
- 컨테이너가 시작 직후 또는 일정 시간 뒤 죽고 `CrashLoopBackOff`로 이어진다.
- 메모리 사용량이 limit에 가깝게 올라간 뒤 재시작이 발생한다.

## 원인 찾기
1. Pod의 `last_termination`이 OOMKilled인지 확인한다. exit code 137만 있고 사유가 없으면 노드 메모리 압박도 의심한다.
2. 배포 이력에서 메모리 limit이 줄었는지, 또는 새 리비전에서 메모리를 많이 쓰는 설정(캐시 적재, 데이터 사전 로딩 등)이 추가됐는지 비교한다.
3. 메모리 사용량 추세가 서서히 오르다 죽는 패턴이면 메모리 누수, 시작 직후 죽으면 limit 대비 필요량 부족이다.

## 조치
- 새 리비전 배포 직후 발생: **직전 리비전으로 롤백**해서 먼저 서비스를 안정화한다.
- 실제로 더 많은 메모리가 필요한 변경이라면 메모리 limit 상향을 검토한다. limit 수정은 KubeOps Copilot의 자동 실행 범위 밖이므로 운영자가 매니페스트를 수정해 배포한다.
- 복제본 증설(scale)은 Pod 하나가 쓰는 메모리를 줄이지 못하므로 OOM 해결책이 아니다.
- 재시작은 같은 limit으로 다시 뜨기 때문에 효과가 없다.

## 검증
- 롤백 또는 limit 조정 후 OOMKilled가 다시 발생하지 않는지, 메모리 사용률이 limit의 80% 아래인지 확인한다.
