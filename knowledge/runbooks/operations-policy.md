# 운영 정책: KubeOps Copilot 조치 범위와 승인 절차

## 자동 실행이 허용된 조치
- **재시작(restart)**: Deployment의 Pod를 순서대로 새로 띄운다. 일시적인 상태 이상에 쓴다.
- **롤백(rollback)**: 직전 리비전의 Pod 템플릿으로 되돌린다. 최근 배포가 원인일 때 쓴다.
- **복제본 조정(scale)**: 1~6개 범위에서 복제본 수를 바꾼다. 부하 증가·감소에 쓴다.
- 대상은 `demo` 네임스페이스의 Deployment로 제한한다.

## 실행할 수 없는 조치
- 삭제, 리소스 limit 수정, Service·ConfigMap·Secret 수정, 다른 네임스페이스(특히 kube-system) 변경은 자동 실행하지 않는다.
- 이런 조치가 필요하면 Copilot은 운영자가 할 일을 안내만 한다.

## 승인 절차
1. Copilot이 근거와 함께 조치를 제안한다 (대상, 예상 영향, 위험).
2. 가드가 허용 범위를 검사한다. 범위 밖이면 승인 단계로 넘어가지 않는다.
3. 운영자가 승인해야만 실행된다. 거절하면 실행하지 않고 기록만 남긴다.
4. 실행 후 롤아웃 완료, Pod 상태, 오류율, 응답 시간을 조치 전과 비교해 검증한다.
5. 질문, 근거, 제안, 승인자, 실행 결과, 검증 결과는 이력에 저장되고 장애 사례로 축적된다.

## 이중 안전장치
- 코드의 허용 목록 검사와 별개로, Copilot 전용 ServiceAccount는 RBAC로 demo 네임스페이스의 Deployment 패치·스케일만 허용된다.
- 코드가 잘못되어도 API 서버가 범위 밖 요청을 거부한다.
