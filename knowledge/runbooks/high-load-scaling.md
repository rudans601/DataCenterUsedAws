# 런북: 부하 증가와 복제본 조정

## 증상
- 요청량(req/s)이 평소보다 크게 늘었다.
- p95 응답 시간이 늘고, CPU 사용률이 limit에 가깝거나 CPU 스로틀링 비율이 높다 (25% 이상이면 주의).
- 오류율은 크게 오르지 않을 수 있다. 느려지기만 하는 경우가 많다.

## 판단 기준
- CPU 스로틀링이 높고 응답 시간이 늘었으면 Pod 수가 부족한 것이다 → **복제본 증설(scale)**.
- 목표 복제본 수는 대략 `현재 복제본 × (현재 CPU 사용 / 목표 사용률 70%)`로 잡고, 허용 범위(최대 6개) 안에서 정한다.
  예: 2개 Pod가 limit의 100%를 쓰고 있으면 2 × 100/70 ≈ 3 → 여유를 두어 4개.
- 요청량은 그대로인데 지연만 늘었다면 부하 문제가 아니라 의존 서비스나 최근 배포를 먼저 의심한다.
- 메모리 부족(OOM)은 증설로 해결되지 않는다.

## 조치
- 운영자 승인 후 복제본 수를 늘린다. 노드 자원이 부족하면 Pod가 Pending이 될 수 있으니 노드 여유를 함께 본다.
- 부하가 줄어든 뒤에는 복제본을 원래대로 줄여 자원을 반납한다.
- 장기적으로는 HPA(Horizontal Pod Autoscaler) 설정을 검토한다.

## 검증
- 증설 후 새 Pod가 모두 Ready인지, p95 응답 시간과 CPU 스로틀링이 줄었는지 확인한다.
