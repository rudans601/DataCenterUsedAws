# Ready 상태인 서비스의 배포 후 지연
버전 2.0 · 배포 회귀, p95 상승, 5xx

## 확인할 근거
Pod가 모두 Ready여도 사용자의 요청은 실패하거나 늦을 수 있다. 배포 전후 같은 주소의 요청 결과, CPU·스로틀링과 요청량, 직전 리비전 대비 변경을 확인한다. 처리 지연으로 완료된 초당 요청 수가 오히려 줄어들 수 있다. 트래픽 급증, 외부 의존성 지연, 배포 이후 변경을 각각 검토한다.

## 운영자 승인

[approval.rollback] 새 배포의 변경과 지연 시작 시점이 맞고 직전 버전이 정상 처리했던 근거가 있으면 운영자 승인 후 직전 리비전으로 롤백한다.

이미 사용자 트래픽을 받는 버전을 되돌리면 서비스 전반에 영향이 있다. 대상·직전 버전·예상 영향을 먼저 알린다. 원인이 불명확하면 현재 버전에서 나타나는 증상과 필요한 추가 표본을 인계한다.

## 결과 확인
Ready 수, 엔드포인트, 전후 응답 시간·오류율을 확인한다. 롤아웃이 끝나도 실제 요청이 느리면 부분 개선 또는 미복구로 기록한다. 시험 도구가 원래 설정을 다시 넣은 시점은 별도로 남긴다.
