# 컨테이너 반복 종료와 메모리 부족
버전 2.0 · CrashLoopBackOff / OOMKilled
이벤트: BackOff, OOMKilled, CrashLoopBackOff

## 조사 순서
CrashLoopBackOff는 재시작 사이에 대기하는 상태다. 이전 컨테이너 로그, 마지막 종료 사유와 코드, 재시작 횟수의 증가, 해당 Pod의 리비전을 확인한다. unknown flag, invalid argument는 최근 실행 인자와 대조한다. OOMKilled는 컨테이너 메모리 제한과 재시작 전 증가 추세를 확인한다. exit 137만으로 메모리 부족이라고 단정하지 않는다.

## 선택할 조치
새 버전에서만 문제가 시작됐다면 실패한 새 리비전의 격리와 롤백 절차를 확인한다. 이전 버전도 실패했거나 배포 이전부터 메모리가 계속 늘었다면 로그와 메모리 추이를 개발자에게 인계한다. 메모리 한도와 노드 설정은 사람이 검토한다.

[approval.restart] 외부 의존성이 회복됐다는 증거가 있고 한 Deployment의 초기화만 계속 실패할 때에는 운영자 승인 후 해당 Deployment의 재시작을 한 번 시도한다.

같은 잘못된 인자나 메모리 한도로 재시작하면 문제가 반복될 수 있다.

## 종료 기준
새 Pod가 모두 Ready이고 재시작 횟수가 다시 증가하지 않는지 확인한다. 요청 오류·지연을 전후 비교하고 반복 종료가 남으면 로그, 대상 리비전, 남은 메모리를 사람에게 전달한다.
