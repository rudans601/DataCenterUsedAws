# 앱 응답과 Kubernetes 작업 진행 확인
버전 2.0 · API timeout / scheduling / controller / etcd NOSPACE

두 지점의 API 조회와 워커의 앱 HTTP를 따로 확인한다. 한 지점에서만 시간 초과가 계속되면 해당 접속 경로를 담당자에게 인계한다. 두 지점 모두 반복 실패하면 클러스터 운영자에게 인계한다. 읽기 요청만 관측한 상황에서 쓰기의 성공이나 실패는 미확인으로 기록한다.

목표 변경이 저장된 뒤 여러 차례 조회한다. 새 Pod가 생기지 않았으면 생성 단계가 지연된 것이다. 새 Pod가 있고 nodeName이 비어 있으면 배치 단계다. 워커 적합성, FailedScheduling 이벤트, 스케줄러 리더의 갱신 시각을 비교한다. 배치되지 않았다는 사실만으로 원인을 확정할 수 없다.

읽기가 성공하고 쓰기가 반복 실패하면 저장 경로를 인계한다. NOSPACE 알람이 있어야 공간 한도로 원인을 좁힐 수 있다. 변경 응답과 저장된 값의 후속 조회를 확인한다.

서비스 요청이 정상이어도 위 작업이 막히면 주의로 기록한다. 마지막 확인까지 문제가 지속되면 운영자에게 인계한다. 관련 작업이 정상으로 돌아오고 앱도 정상이라면 자동 관찰로 종료한다. 재생 기록을 근거로 실제 클러스터에 변경을 실행하지 않는다.
